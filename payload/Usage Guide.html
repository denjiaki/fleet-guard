FFleet Guard
USAGE GUIDE

Launch once.
Keep moving.

Fleet Guard watches Claude tasks inside Paseo and hands unfinished work to your configured fallback providers after a real quota or session-limit failure.

Everyday use

1Open the combined shortcutUse Fleet Supervisor - On Paseo on your Desktop or Start Menu instead of the original Paseo shortcut.
2Work in a root Claude taskUse Claude normally in Paseo. There is no Fleet chat and nothing to activate manually.
3Let the handoff happenAfter a recorded limit, Paseo providers appear as a child task named Fleet Guard · provider and continue the active request.
Invisible and Paseo-scoped. Fleet Guard uses a native windowless launcher, so it does not appear in Alt+Tab or on the taskbar. Once Paseo's daemon is gone for 20 seconds, Fleet Guard exits completely. Closing only the visible window may leave the daemon running; fully quit Paseo when you want both stopped.

Continue a job that already stopped

Already visible in Paseo

Launch Fleet Supervisor - On Paseo. It scans recent root Claude tasks automatically, including failures from before the Guard started. You do not need to resend the prompt.

Currently outside Paseo

Import or reopen the Claude conversation in Paseo first. Fleet Guard cannot inspect Claude Desktop, claude.ai, Cursor, or another app directly.

What the handoff contains

The fallback receives the active user request, a compact recent timeline, the working directory and workspace, and a completion contract. It must finish and verify the task, report that another provider should continue, or stop for genuinely necessary human input.

Choose how persistence works

Return to Claude

After the provider list and cooldown, Guard first retries the original Claude task—the “father”—then works through the fallback priority list again if Claude is still limited.

Cycle fallback providers

Guard repeatedly follows the priority list without retrying Claude. When reuse is enabled, it returns to each provider's existing child instead of starting a fresh conversation.

One pass, then stop

Each provider gets its configured turn and nudges once. When the list ends, Guard becomes dormant. This matches the older behavior.

Nudges and completion checks

An unfinished child can receive extra turns in the same session. The completion challenge asks it to inspect the diff and tests once more before Guard accepts that the shared task is finished.

Persistent does not mean Windows-resident. Cooldown cycles continue only while Paseo is running. Fully quitting Paseo, including its daemon, pauses the chain; reopening with the combined shortcut resumes a recent interrupted chain from its saved cycle and child IDs.

Permissions and provider limits

Guard-created tasks use automation-friendly modes: Codex auto-review, a dedicated Fleet Cursor connection with Cursor's yolo/trust flags, Copilot allow-all, Antigravity's non-interactive permission option, and a Fleet-only OpenCode profile for local models. Those choices affect only fallback tasks created by Fleet Guard. Every cloud provider still uses its own installed CLI, account, subscription, policy, and quota. Fleet Guard does not bypass or reset limits.

Add a model running on this PC

Choose Local model on the provider page. Fleet Guard uses OpenCode as the coding-agent harness, so the model receives real read, edit, and shell tools in the shared Paseo workspace instead of receiving only a copied text prompt.

Install the two pieces

Install OpenCode plus a local server such as Ollama, LM Studio, or llama.cpp. Start or load a coding-capable model in that server.

Connect the endpoint

Click Configure. Ollama normally uses http://127.0.0.1:11434/v1. Click Find models, choose one returned by the server, and add it to the priority list.

Private by construction

The endpoint must resolve to this same PC. Fleet Guard does not request or store a local API key, and its OpenCode profile does not alter your normal OpenCode settings.

Choose an agentic model

Reliable tool calling matters more than chat quality. For Ollama, a coding model with roughly 16k-32k context is a sensible starting point.

Where each fallback appears

Codex, local models, Cursor, and Copilot

These are Paseo providers. When Fleet Guard reaches one, it creates a visible child task under the halted Claude task.

Antigravity

Antigravity runs as an external CLI worker, so it does not create a Paseo tab. Its start, result, and any error are written to the Guard log and handoff report.

Understanding setup sign-in status

Signed in means Setup found the provider's credential entry without reading or copying its secret. Live test passed means you deliberately chose Verify and the provider answered one short no-tools request. Verify is optional and uses provider quota; Antigravity may report a large fixed input context even for this short probe.

Status, configuration, and removal

Change the policy

Open Fleet Guard Settings from the Start Menu. It reloads your saved provider selection, priority order, and continuation choices.

See what happened

Open STATUS.cmd in %LOCALAPPDATA%\PaseoFleetGuard. It shows the current policy, cycle, next retry, recent activity, and handoff state.

Remove Fleet Guard

Open UNINSTALL.cmd in the installation folder. It stops the Guard and removes the combined shortcuts. Logs and configuration remain for recovery.
